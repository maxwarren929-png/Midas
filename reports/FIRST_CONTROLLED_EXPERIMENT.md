# Midas First Controlled Experiment Suite

## 1. Executive Summary

The suite ran on the expected baseline commit, `8f83064807f68850aed3f3b922d643f6f36fabff`, using the offline synthetic CSV. All 20 controlled runs (four conditions, five seeds: 41--45) completed with `Completed` lifecycle and no unexplained failure. The final repository test suite passed 79 tests.

**Verdicts:**

* **Mechanically valid:** Yes for the tested training runs. Checkpoint/resume reports matched exactly for all four conditions at seed 41, and the frozen validation command completed deterministically.
* **PPO learning operational:** Yes. Actor and critic head parameters changed on all PPO runs; hidden and recurrent deltas were exactly zero; birth genomes remained unchanged.
* **Evolution operational:** Yes. Evolution-enabled CLI runs recorded deaths, two-parent reproductions, crossover, mutation, new generations, and valid ancestry.
* **Improvement detected:** No consistent improvement. PPO conditions were below the static control across all five seeds. Evolution-only had a small mean uplift over control (3/5 seeds higher), but this is preliminary and not robust across benchmarks.
* **Benchmarks trustworthy:** Exposure semantics are covered by regression tests and the benchmark CLI remains non-learning/non-evolutionary. Benchmark values are still synthetic, short-horizon references rather than evidence of profitability.

## 4. Configuration and Calibration

The common template is [`configs/experiment-common.toml`](../configs/experiment-common.toml); because the loader has no include mechanism, each condition is a complete copy. The four condition files differ only in `learning.implementation` and `evolution.enabled`; [`config-diff.txt`](config-diff.txt) is generated by `experiments/compare_configs.py` and reports exactly those two fields.

All conditions share the same synthetic data, assets, architecture, costs, reward defaults, seed per replicate, and date splits. The frozen training split is 2020-01-02 through 2020-01-27 (16 simulation steps after feature generation); validation is 2020-01-28 through 2020-01-31, and test is 2020-02-03 through 2020-02-05.

The first calibration used `bankruptcy_threshold=9700` and produced no deaths. Its raw output is `experiment-calibration-initial-no-deaths.txt`. One allowed adjustment raised the threshold to `9950`; the frozen calibration then produced 6 deaths and 6 replacements from 16 founders, approximately 37.5% founder mortality, with maximum generation depth 2. No further pressure tuning was performed.

## 8. Recoverable-Failure Learning Evidence

The controlled market runs naturally generated zero policy failures, so failure-learning evidence was collected separately with deterministic failure injection. These tests passed:

* `recoverable_invalid_output_creates_penalized_chronological_rollout_entry`
* `recoverable_policy_failure_has_one_fallback_and_advances_normally`
* `masked_failure_reward_remains_in_chronological_returns`

Together they verify a single fallback event, a penalized chronological rollout entry, actor/critic masking, and GAE continuity. Raw `cargo test --nocapture` output is in `failure-learning-invalid-output.txt`, `failure-learning-fallback.txt`, and `failure-learning-gae.txt`.

## 9. Evolution Evidence

Evolution-only averaged 3.2 deaths, 3.2 two-parent reproductions, and maximum generation depth 1. PPO+evolution averaged 5.8 deaths and 5.8 reproductions, with maximum generation depth 2. The evolution reports contain completed-life records, fitness, parent genome IDs, crossover/mutation records, lineage IDs, and diversity metrics. No random fallback birth or diversity relaxation was needed in these runs. [`evolution-diagnostics.csv`](evolution-diagnostics.csv) is the compact per-run table.

The representative seed-41 PPO+evolution report includes children with two parent IDs, distinct genome IDs, and fresh lifetime state. Non-Lamarckian inheritance is also covered by the Prompt 2 tests: lifetime head updates do not alter the birth genome and reproduction uses birth genomes.

## 11. Checkpoint Determinism

For seed 41 in every condition, the experiment was run uninterrupted and separately to step 8, checkpointed, resumed, and compared at report level. All four comparisons were exact (`equivalent=True`, 16 steps). This includes full-head lifetime state, rollout/optimizer state, IDs, evolution state, and domain-derived performance summaries. Raw partial/resumed outputs are retained, with the summary in [`checkpoint-resume-equivalence.txt`](checkpoint-resume-equivalence.txt).

The new `evaluate` command restores a completed checkpoint's trained lifetime parameters, resets recurrent state and portfolios, disables learning/evolution/replacement, and evaluates on another split. A representative validation run for all four conditions at seed 41 completed with zero updates and was byte-identical on repeat; see [`frozen-evaluation-summary.txt`](frozen-evaluation-summary.txt) and `*-evaluation-validation.txt`.

## 12. Training/Evaluation Split

Training used only the frozen training range. The new frozen-evaluation command uses the validation range with learning and evolution disabled; it does not write back parameters. Seed-41 validation mean final net worth was 10008.66 (control), 9989.56 (PPO), 10014.62 (evolution-only), and 10004.97 (PPO+evolution), all below the validation equal-weight and buy-and-hold references near 10034.35. This is one validation replicate per condition and is descriptive only.

## 13. Bugs and Fixes During the Suite

No simulation-core correctness bug blocked the controlled runs. The experiment tooling fixes were:

* Added `midas-diagnostics` to expose event counters, PPO metrics, parameter deltas, and ancestry without changing simulation behavior.
* Added `midas-cli` as the package default binary so existing `cargo run -p midas-cli -- ...` commands remain valid with the diagnostics binary present.
* Added `simulate --steps N` for reproducible partial-checkpoint experiments.
* Added frozen `evaluate --checkpoint ... --split validation|test` support and a regression test proving it disables learning.

## 14. Limitations

The dataset is a 24-session synthetic market, the horizon is 16 steps, and the backend is CPU-only. The action distribution remains single-asset capped categorical rather than a general multi-asset simplex. Ordinary runs produced no policy failures, so failure learning is demonstrated by focused deterministic tests rather than prevalence estimates. Five seeds are enough to expose gross regressions but not to support significance tests. The evaluation split results cover one seed per condition. No claim of intelligence, profitability, or evolutionary success is warranted.

## 15. Recommended Next Experiment

Use a longer, independently generated market with a pre-registered pressure and evaluation protocol, keep the same four-condition design, add several more seeds, and record fixed observation-policy diagnostics before and after training. Treat PPO/evolution changes as operational mechanisms first; require consistent improvements over static control and all benchmarks before interpreting them as useful behavior.
